# JuMCNet on Raspberry Pi 5: MNN FP32 and Convolution–SiLU Fusion Tests

- Reference: the existing attention-fused ONNX FP32 model with C++ lookup-table and HWC→CHW preprocessing. The settings retain 4 inference threads, a single ORT inter-op thread, sequential execution, ALL graph optimizations, and disabled spinning; the CPU governor is unchanged.
- Method 1: MNN 3.6.1 CPU with precision=high. Conversion uses the standard ONNX model with the same weights, optimizeLevel=1, and optimizePrefer=2; GELU approximation, weight quantization, and denormal-value alignment are disabled. FP16 is not used.
- Method 3: in the accepted attention-fused graph, 7 strictly matching pairs of 3×3 depthwise convolution and SiLU are combined into native FP32 NEON operators. SiLU is computed directly from convolution results in registers before writing, using the existing ORT thread pool. Initial weights remain byte-identical, and the 9 Attention nodes are unchanged. Constraints are padding=1, dilation=1, stride=1/2, and depth multiplier=1.
- Numerical screening: fixed seed5555 and 48 saved validation images (8 per class); classes must match exactly, values must be finite, and logits must satisfy np.allclose(atol=rtol=2e-4). Fusion operators are also independently checked for odd/even dimensions, boundaries, and both stride values.
- Speed screening: separate processes, fixed native preprocessing, and alternating baseline/candidate order. Each configuration uses 100 warmup iterations, 240 inference-only measurements, and 144 measurements including preprocessing (the same 48 validation images repeated 3 times). Of 3 paired groups, at least 2 must improve, with an overall benefit >0.5%. If MNN fails numerical checks, its latency is diagnostic only and the candidate is not formally adopted.
- Independent confirmation: fused and baseline implementations are remeasured in B-A-A-B order. After verification, the candidate implementation is fixed before full testing across 5 training seeds, each sharing the same 2325 test images; the test set is not used to select the implementation.
- Formal testing: each configuration runs in a separate process with 100 warmup iterations, 500 inference-only measurements, and the complete serial pipeline for 2325 images. Total latency includes file reading/decoding, RGB conversion, resizing, cropping, normalization and layout conversion, inference, and softmax/argmax; it excludes model startup, networking, and writing results to disk. Both configurations use the same test script.
- These experiments do not support conclusions about on-site camera acquisition latency, power consumption, or long-term operation. Repeated latency measurements are not independent training seeds; five-seed means and sample standard deviations are aggregated separately.
- Only the current seed's device models are retained at any time; new results, logs, and models are verified with SHA256 and archived before the task's temporary models are cleared.
